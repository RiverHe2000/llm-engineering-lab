# loraeval · LoRA from scratch with rigorous evaluation

Parameter-efficient fine-tuning implemented from first principles, applied to a finance
task, and evaluated the way a model-risk reviewer would want: confidence intervals, paired
significance tests, calibration, and a fully auditable run directory per experiment.

**Task.** 3-class sentiment on the *Financial PhraseBank* (Malo et al., 2014): 2 264
sentences from financial news with unanimous annotator agreement, e.g.
*"Operating profit rose to EUR 13.1 mn from EUR 8.7 mn"* → positive. Class balance is
61 % neutral / 25 % positive / 13 % negative, so macro-F1 is the headline metric.

| | |
|---|---|
| Quality gates | `ruff`, `mypy --strict`, **83 tests** (all offline, CPU, ≈ 6 s), **98 % branch coverage** |
| Base model | `distilbert/distilbert-base-uncased` (67 M params) — any `AutoModelForSequenceClassification` works |
| Headline result | **LoRA r = 8 trains 1.1 % of the parameters and matches full fine-tuning** (95.9 % vs 94.4 % accuracy, McNemar p = 0.125) |

## 1. What is implemented

| Piece | File | Notes |
|---|---|---|
| LoRA layer | `lora.py::LoRALinear` | `y = Wx + b + (α/r)·B·A·x`; `A` Kaiming-init, `B` zero, so the adapted model equals the base model at step 0. `merge()` folds `ΔW` into `W` for zero-overhead inference; `unmerge()` restores it bit-for-bit. |
| Model surgery | `lora.py::inject_lora` | Regex over `named_modules()` picks which `nn.Linear`s to wrap (`q_lin|v_lin` by default). `mark_only_lora_as_trainable` freezes everything else except the head. Adapter-only `state_dict` (0.3 MB vs 268 MB). |
| Strategies | `models.py::apply_strategy` | `head` (linear probe), `lora`, `full`, all through one code path so the comparison is fair. |
| Data | `data.py` | Downloads the raw zip via `huggingface_hub` (the old `datasets` loading script is no longer supported), parses `sentence@label` (Latin-1), **stratified** train/val/test split, dynamic padding. |
| Training | `train.py` | AdamW (no decay on 1-D params), linear warm-up/decay, bf16 autocast, grad clipping, per-epoch val macro-F1, early stopping, best-epoch restore, full seeding (CPU runs are bit-reproducible — tested). |
| Metrics | `metrics.py` | Confusion matrix, per-class P/R/F1, macro-F1, NLL, **expected calibration error**, **percentile bootstrap CIs**, **McNemar's paired test** (exact binomial / continuity-corrected χ²). Pure NumPy, unit-tested against hand-computed values. |
| Reporting | `report.py`, `experiment.py` | Every run writes `config.json`, `metrics.json`, `predictions.npz`, `weights.safetensors`. `loraeval compare` renders the Markdown below from those files — nothing is typed in by hand. |

## 2. Results (RTX 4070, bf16, seed 42, test n = 340)

Generated by `loraeval compare … --baseline full_ft` → [docs/RESULTS.md](docs/RESULTS.md).

| Run | Trainable params | Accuracy % [95 % CI] | Macro-F1 % [95 % CI] | ECE | Train time |
|---|---:|---|---|---:|---:|
| head_only | 592 899 (0.89 %) | 85.0 [80.9, 88.8] | 79.0 [73.6, 83.9] | 0.039 | 4 s |
| lora_r4 (q,v) | 666 627 (0.99 %) | 95.6 [93.2, 97.6] | 93.9 [90.6, 96.9] | 0.033 | 6 s |
| **lora_r8 (q,v)** | 740 355 (1.10 %) | **95.9 [93.8, 97.9]** | **94.2 [91.0, 97.1]** | 0.041 | 6 s |
| lora_r16 (q,v) | 887 811 (1.32 %) | 96.2 [94.1, 97.9] | 94.5 [91.4, 97.3] | 0.045 | 6 s |
| lora_r8 (all linear) | 1 256 451 (1.86 %) | 94.4 [91.8, 96.8] | 91.9 [88.1, 95.2] | 0.045 | 9 s |
| full_ft | 66 955 779 (100 %) | 94.4 [91.8, 96.8] | 92.2 [88.6, 95.6] | 0.033 | 10 s |

Paired comparison against full fine-tuning (McNemar, same 340 test sentences):

| Run | Δ accuracy | discordant pairs (full right / run right) | p-value |
|---|---:|---:|---:|
| head_only | −9.4 pts | 36 / 4 | < 0.0001 |
| lora_r4 | +1.2 | 2 / 6 | 0.289 |
| lora_r8 | +1.5 | 1 / 6 | 0.125 |
| lora_r16 | +1.8 | 0 / 6 | 0.031 |
| lora_r8 (all linear) | 0.0 | 5 / 5 | 1.000 |

**How to read this.**

* A linear probe on frozen DistilBERT is clearly insufficient (−9 points, p < 1e-4): the
  encoder itself has to adapt to financial language.
* LoRA on the attention q/v projections recovers everything full fine-tuning gets, with
  1 % of the trainable parameters and a 0.3 MB artefact instead of 268 MB. The +1.5-point
  edge over full FT is *not* statistically significant (8 discordant pairs); the honest
  claim is "indistinguishable", and a plausible mechanism is that the low-rank constraint
  regularises on a 1 584-sentence training set.
* Increasing `r` from 4 to 16 changes accuracy by 0.6 points — inside the noise. The
  rank-16 row reaches p = 0.03, but with six comparisons against the same baseline that
  is what one would expect from multiple testing; I would not report it as a real effect.
* Applying LoRA to *all* linear layers at the same `r` did not help here (it did in QLoRA
  on much larger models); more adapted parameters ≠ better on 1.6 k examples.
* Calibration is good across the board (ECE 0.03–0.05), i.e. a 90 % confident prediction
  is right about 90 % of the time — which is what matters if these scores feed a threshold.
* The 95 % CI on accuracy is ±2–4 points at n = 340. Any "state-of-the-art by 0.8 points"
  claim on this dataset without an interval is noise.

## 3. Tests: what each one proves

| Test | Property |
|---|---|
| `test_lora::test_equals_base_at_init` | With `B = 0` the adapted layer is exactly the base layer. |
| `test_lora::test_merge_unmerge_round_trip` | Merged forward == unmerged forward; unmerge restores `W` to 1e-6. |
| `test_lora::test_gradients_flow_only_into_adapter` | Base weights receive no gradient. |
| `test_lora::test_model_output_unchanged_at_init` | Injecting LoRA into a whole HF model changes nothing until training starts. |
| `test_metrics::test_exact_branch_matches_binomial` | McNemar exact p equals `2·0.5^n` for `(b, c) = (10, 0)`. |
| `test_metrics::test_perfectly_calibrated_is_zero` | ECE is 0 when 80 %-confident predictions are right 80 % of the time. |
| `test_metrics::test_interval_shrinks_with_more_data` | Bootstrap CI width falls faster than 1/2 when n grows 16×. |
| `test_data::test_stratified_proportions_and_disjointness` | Every split has the same label mix and no overlap. |
| `test_train::test_training_is_reproducible` | Two seeded runs give bit-identical adapters. |
| `test_train::test_lora_learns_and_only_adapter_changes` | After training, every frozen tensor is unchanged. |
| `test_experiment::test_lora_experiment_writes_auditable_artifacts` | The saved adapter, applied to a fresh base model, reproduces the run's test predictions to 1e-5. |

All tests use a randomly initialised 23 k-parameter DistilBERT and an in-memory word-level
tokenizer, so CI never downloads anything (`HF_HUB_OFFLINE=1`).

## 4. Reproduce

```bash
pip install -e ".[dev]"
pytest && ruff check . && mypy

loraeval run --config configs/lora_r8.yaml            # downloads DistilBERT + the dataset once
loraeval run --config configs/full_ft.yaml --override train.epochs=3
loraeval compare runs/head_only runs/lora_r8 runs/full_ft --baseline full_ft --out docs/RESULTS.md
loraeval predict --run runs/lora_r8 --text "Operating profit rose to EUR 13.1 mn" --text "The company cut its guidance"
```

Swap the base model in the YAML (`model_name: Qwen/Qwen2.5-0.5B`, `target_modules: '\.(q_proj|v_proj)$'`)
— nothing else changes.

## 5. Design decisions

* **Own LoRA rather than `peft`.** The point is to show I understand the mechanism
  (scaling by `α/r`, zero-init of `B`, merge semantics) and can test it. In production I
  would use `peft` and keep these tests as the acceptance suite.
* **Statistics in the report, not in a notebook.** CIs and paired tests are part of the
  artefact every run produces, so a reviewer cannot be shown a lucky number.
* **Predictions are saved, not just metrics.** Paired tests need per-example outcomes;
  saving `predictions.npz` makes any later comparison possible without re-running.
* **Stratified split with a fixed seed, and the split is recorded** in `metrics.json`
  (sizes and label distribution per split), so the test set is auditable.
* **Injection points for tests.** `run_experiment` accepts a model, tokenizer and examples,
  and the CLI's loaders are module-level functions that tests monkeypatch — the whole CLI
  path is exercised offline.

## Related projects

This repository is one of three standalone projects that together cover a Transformer's
life-cycle — build it, adapt it, serve it — all held to the same engineering standard
(ruff, `mypy --strict`, offline CPU test suites with coverage gates, matrix CI):

* **transformer-from-scratch** (`nanoformer`) — a LLaMA-style decoder, byte-level BPE and an
  AMP trainer with bit-exact resume, written from first principles.
* **lora-finetune-eval** (`loraeval`) — LoRA implemented from scratch and a statistically
  rigorous evaluation harness, applied to financial sentiment classification.
* **llm-inference-server** (`llmserve`) — KV-cached batched generation, dynamic batching,
  INT8, Prometheus metrics, FastAPI and Docker for any Hugging Face causal LM.
